## 6. 阿里云主站与后台部署（独立规划章节）

### 6.1 决定与拓扑

采用“两台现有云服务器＋Hermes PC浏览器采集节点”，单生产者、单公开读端；不是完全脱离家庭PC的全云方案。此处“后台”指采集/处理/发布作业与私有运行状态，不新建后台管理平台。调研和资源证据见[报告](../../research/2026-10-04-aliyun-deployment/REPORT.md)。

```text
Hermes PC：Edge持久登录profile → CDP :9223 / Playwright MCP :8931
  └─ 既有反向SSH隧道 → 生产机回环 :58933 / :58931
     微信正文抓取依赖此链；扫码/验证码需要人工

ack-node-2 47.117.244.253（生产端）
  微信/RSS → 现有SQLite原库 → 翻译/实体/图谱/解读/Wiki
  → accepted + receipt → 发布包构建/校验
                │ 完整、不可变的public release，经SSH传输
                ▼
ack-node-1 47.103.73.20（服务端）
  staging → 校验 → releases/<id> → current原子切换
  Caddy HTTPS → 127.0.0.1:8788 公共只读API+构建后站点

Mac：独立私有文章快照 + 本地8788阅读；从云端拉公开版本
     不再承担云端每日知识生产的必要调度
```

两机各8核/约14.7GiB；实测查询机无80/443监听，有约4.19GiB可用内存、43.95GiB磁盘，适合先部署轻量候选；不是负载测试结论。采集机80已有监听且承载较重处理，将主站放查询机可以减少竞争和代理冲突。两机不是高可用：读机故障网站仍会中断，生产机故障则网站继续提供旧版本。

单机以后若有实测降本需求再评估；当前不搬原始写库、LightRAG/Qdrant或凭据，不退役第二台机器/旧服务。不新增ECS、RDS、Redis、队列、NFS共享库、Kubernetes部署或负载均衡。

### 6.2 必要架构调整

1. **生产与搬运分离**：对现有refresh入口做小范围拆分，生产端直接读取本机原库的一致性快照、复用本机DeepSeek客户端；跨机传输只负责发布。不让生产机再SSH回自己，不复制第二个producer实现。前端预先构建为版本化代码产物，内容刷新复用它，不在每小时刷新时装依赖。
2. **唯一调度所有者**：云端systemd timer接管现有每日额度/阶段缓存/失败账本；Mac只镜像阅读。迁移时先停旧生产调度并等运行结束，转移账本和accepted缓存、核hash，再启云端；两个机器上的flock不是分布式锁，不能靠它防双计费。
3. **发布合同独立于旧KG同步**：只传public.sqlite、完整site、被引用的公开媒体和manifest。用现有builder/validator，同版引用闭合；不得把私有原文库、凭据、工作目录作为静态根目录。原始SQLite导出用backup API；不跨机器共享WAL文件。
4. **公网与私有分实例**：公网app不传local_articles_database/receipt，禁用MCP挂载（显式开关，现有调用默认行为保留，公网启动显式关闭）；只有公开读API/静态站。私有全文和运维状态保留Mac，必要时用已有SSH隧道访问独立loopback实例。不能依赖反代后的loopback请求地址作身份认证，不建设新账号平台。
5. **版本一致性**：一次HTTP请求固定一个release，详情/证据跟随该release；旧静态资源保留可访问。沿现有release_id/manifest机制补必要固定路径，避免current切换造成数据库、HTML和资源混版，不引入发布服务。

### 6.3 部署形态与配置默认值

生产端保留原服务资源边界，知识生产与100元回填串行执行；先不再扩大内存。服务端独立非root运行用户与venv，版本目录部署，仅持有公开读包。用systemd托管单worker Uvicorn，绑定127.0.0.1:8788；候选初始MemoryHigh=512MiB、MemoryMax=1GiB，经真实发布规模校验后调整，不影响旧MCP/KB/embedding。

查询机部署一份Caddy作HTTPS入口（若实施时已有owner则复用其受管配置，不抢端口）；代理到公共reader。只为新站点开放必要HTTP/HTTPS入口，不改现有其他服务规则。域名不猜定，公网DNS/TLS须在确认所有权、地域及备案后配置；缺失时停在SSH隧道候选，其他实施可继续。公网域名HTTPS条件与内地备案要求见调研一手来源。

跨机默认复用已授权SSH路径；实施前核互通和主机指纹。缺少主机间授权即该发布步骤BLOCKED，不私自生成/搬运凭据或换通道。后台接收包写staging，校验路径、hash、SQLite和引用闭包后同文件系统切换current；传输/校验失败只记录并下周期接续，旧版继续服务。不通过旧向量差量同步脚本发布网页。

### 6.5 回滚、运维及退出门

此方案不要求重写业务架构；只补单一生产所有权、可搬运发布包和公开读实例三个部署接缝。公网就绪状态、峰值容量、网络费用与主机间授权仍是实施预检事实，不用未经证实的假设冒充通过。

### 6.6 用户指出的关键修正：Hermes CDP与MP人工登录

2026-10-04追加核查：生产机`.env`允许列出的非秘密端点为CDP localhost:58933、MCP 127.0.0.1:58931；远端实际scraper默认CDP→MCP。既有部署档案确认Hermes反向隧道映射到本机9223和8931，因此两路径共享同一浏览器故障域。

本轮生产机58933 `/json/version`超时；Hermes本机9223 `/json/version`报URLError。Hermes的playwright-mcp/aliyun-tunnel/hermes-gateway虽active，不能证明CDP端到端可用。按此证据，微信浏览器抓取运行面当前BLOCKED；本轮未启动/重启Edge、隧道或替换通道。未读取cookie值、浏览器页面正文或打印token。

必须区分三件事：

| 行为 | 当前路径 | 是否依赖人工MP登录 |
|---|---|---|
| 获取公众号文章列表 | 极致了API及既有DAJIALA_API_KEY；周扫描timer最近触发9月27日 | 此API调用本身不使用本人的MP Cookie；API额度/可用性另验 |
| 获取文章全文 | Hermes Edge共享context的CDP；MCP也指向同浏览器 | 不是所有公开文章都必需MP登录，但现有稳定浏览器路径依赖PC/浏览器环境；遇登录或验证必须人工处理 |
| 旧MP后台列表API | kol_config保存的token/cookie | 依赖有效后台会话；即便登录有效，接口仍可能单独限流或不可用，不能保证扫码后恢复列表能力 |

保存的MP凭据做了一次只读首页请求：HTTP200、login_marker=true、dashboard_marker=false、has_token_marker=true。token字符串存在不足以证明登录，当前未确认有效；这不是对Edge profile当前登录态的直接检查，因CDP不通无法判定。首次登录、登录过期或微信要求确认/扫码时由用户完成；不承诺全自动续期，也不要求每篇文章重新登录。已有refresh_wechat_cookie脚本包含扫码通知和凭据写回，存在副作用，本轮未运行。

架构与验收据此调整：

1. Hermes PC成为明确的受管采集依赖：开机、网络、Edge持久profile和既有隧道需可用；主站和RSS、已存文章加工不依赖它在线。不能把“Mac退出生产调度”误写成“所有个人电脑退出链路”。
2. 沿现有状态记录新增/规范`browser_unavailable`、`login_required`、`verification_required`、`rate_limited`，与正文缺失、处理失败分开。浏览器不通时停止该轮浏览器请求，延期候选；不得让每篇文章重复耗尽120秒连接超时。
3. 恢复验收次序：Hermes本机CDP元信息→生产机隧道CDP→经现有抓取入口读取一篇已知公开微信正文并通过质量检查→后续自然批次持久化。登录态和列表接口能力分别验证；登录页/验证码壳不得入正文库。
4. 需要用户操作时，记录需要在哪台机器哪个profile登录，私有状态页提示；不新建通知平台、不在本轮发送外部消息。人工完成后下一受控尝试接续成功阶段，不重跑已收费加工。

### 7.3 内容合同与取舍

- **原文**忠实保存；**清洁阅读稿**只做确定性噪声处理与排版；**译稿**保留原意、数字、术语、代码与引用；**改写/解读**明确为派生内容，不能覆盖原文或伪装忠实译文。
- 语言缺失先用现有元信息和可验证内容核定，无法确定则保留unknown，不强行翻译。默认优先中文阅读能力，中文原文的英文版不作为必补项。
- Wiki按定义、组成、适用边界、案例/争议、来源组织；非所有主题都强填所有栏目。新增来源能支持实质变化才更新，不为改变时间戳重生成。
- 作者、公众号/站点、发表时间、抓取时间分别表达；未知不编造，也不把抓取时间冒充发布日期。图片和表格优先补论点所必需的资产，确实缺失时显示缺失说明，不生成替代图。
- 仅元数据记录和被筛除记录不自动全量抓取/翻译。候选去fragment归组不等于内容相同；复用必须核来源修订/hash与对应recipe，不能按同标题合并。
- 本地全文可读仍不以公开审核为前置；私有原文、译文、改写不因内容补全自动进入公网知识包。
