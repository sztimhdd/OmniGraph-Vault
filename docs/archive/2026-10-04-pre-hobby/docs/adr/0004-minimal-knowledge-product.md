# 保留知识产品能力，以总代价决定组件

2026-09-09。延续 ADR 0001–0003；依据用户对 KG、Wiki、可选 AgentRAG 的讨论，以及随后明确要求按 ponytail 重新规划并开始实施。具体引擎的性能和质量尚未验收。

[KNOWN] 用户要求专业知识站、持续更新的 Wiki 和 KG，并允许访客 BYOLLM。最新讨论接受 SQLite 存储带证据的业务图谱、LightRAG 作为高级检索对照；未授权以减少组件数量为由删除已有知识或牺牲高级检索效果。

[INFERRED] 确定的数据合同：稳定来源、文章修订、已接受知识修订、公开发布版本。SQLite 保存实体、别名、类型化关系及主张/关系到证据的关联；原始资料和已接受的知识产物保留版本。Wiki 可跨文章引用，不把每个实体都强制生成一个页面。图引擎内部索引是派生物，不能决定文章是否可读。

[INFERRED] 确定的产品边界：普通浏览/关键词检索不调用生成模型；复杂问题可进入有界 AgentRAG，按需搜索、读证据、查关联、补查并综合。网站与 MCP 共用公开查询逻辑、release_id 和权限。查询工具优先返回证据；不能把另一层模型生成的答案冒充原始证据。返回上下文不等于内部零模型调用。

[INFERRED] SQLite 关系表不自动替代 LightRAG 的实体/关系召回、融合和排序；向量存储与图检索分别裁决。保留现有 LightRAG/Qdrant 为隔离对照和过渡实现，不自动部署到新公开站，也不提前退休。最终每个生产职责只保留一个实现。只有实际质量、容量和维护成本支持时才替换，不写通用图引擎、LightRAG 的自制替身或多引擎插件平台。

[INFERRED] 编排先复用一套现有入口。Prefect 不再是首条链的前置实验；出现明确、重复的调度工作时再说明它替代什么。首版不新增 Celery/Redis、Temporal、LangGraph 或第二 Agent 运行时。保留 Hermes 语义任务及既有 Codex/Telegram 升级方向，不扩展通用恢复系统。

[INFERRED] 第一实施切片是离线公开投影的构建与读取：已接受文章解读、Wiki、关系与引用进入新 SQLite，能重新打开并搜索、读取证据和关联。它不是完整 ingestion、生产知识库迁移、语义质量或站点验收。随后以真实来源接入同一合同，再接站点、BYOLLM、日更和单云切换。

[INFERRED] 收益是推迟不必要的框架安装、减少重复生成与多系统状态管理；代价是首个切片不含高级路径查询、向量替换、图片发布或自动语义加工。这些已明确排入后续产品切片，不以样例测试宣称完成。

实施入口：[当前计划](../superpowers/plans/2026-09-09-vitax-product-architecture.md)。ADR 0002 的永久删除、不可逆迁移、身份凭据和付费资源边界不变；不自动 commit/push。
