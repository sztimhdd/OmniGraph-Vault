# VitaX 本地三模块自动闭环规格

Status: authorized execution / ready-for-agent — 用户2026-10-02明确要求规划后实施；本规格收敛并接续既有三模块票，不另设tracker。

## Problem Statement

本地文章镜像与知识包停在人工导出，采集/翻译/建图已有真实产出却没有自动交接。微信优先的候选排序使RSS在受限批次中长期等待，失败阶段结果和重入需准确，已保存原文不该重复抓取。用户要一个可日常使用、原文/译文/知识/Wiki/实体关联可读的VitaX本地应用。

## Solution

复用一套现有采集/筛选/翻译/建图入口；以同源状态、已有有效产物和既有producer/build-release实现自动接续。原文镜像与已接受知识仍分开权限，但每天由一个本地调度入口更新同一个站点。网页读取全历史快照而不是仅成功ingestion子集；原文缺失、外部访问受限、翻译或生成待处理准确显示，不冒充完成。

## User Stories

1. 维护者希望微信和RSS候选都能在有界批次得到处理，避免一轨占满预算。
2. 维护者希望已抓的合格原文被复用、清洗与过滤，失败不丢成功部分。
3. 维护者希望翻译/改写保持原文、来源及链接，部分失败准确报告并可接续。
4. 维护者希望只有受控请求的失败可重入，普通失败不每轮无限重试。
5. 维护者希望已处理来源有实际实体/关系与持久化结果，不以服务active冒充建图成功。
6. 维护者希望真实文章解读和跨来源Wiki有可核引用，重跑相同输入不重复生成。
7. 维护者希望Wiki更新正文/引用而非仅新建占位页；同主题只由一个指定生产职责处理。
8. 维护者希望本地浏览所有正常历史资料：有真实原文或已有译文的记录可打开；只有元数据的记录仍列出并说明缺失。
9. 维护者希望列表、详情、分页、刷新、来源/引用/实体链接和已有图片路径可用；不承诺修复第三方站点的登录墙/失效URL。
10. 维护者希望自动抓源/处理产物后，本地文章镜像与公开知识版本可自动更新，失败保留上一完整版本。
11. 维护者希望下一日程和重复运行有独立证据，日更不依赖主控会话一直在线。
12. 维护者希望在新10%周额度内得到完成门或明确剩余阻塞，不重置额度、不靠更换provider隐藏失败。

## Implementation Decisions

- 最新读回：5/6GiB资源约束已跨初始化，两次自然运行有微信ok；来源候选始终微信在前而RSS尚未处理，这是新最小修复点。保留源内FIFO、来源隔离与现有拒绝/失败保护；双轨交错调度。
- 抓源名单/调用预算沿用现有：RSS active名单，公众号48唯一目标、原周周期最多20号×2页；不新增付费扫描预算，不绕过登录/付费墙，不关闭TLS。
- 翻译、改写、实体抽取/图写入继续复用既有有效业务入口与Vision路径。各阶段成功/部分失败/失败清楚；原文、已有翻译与旧知识不覆盖丢弃。
- 本地“正常”是已有可读真实正文/译文，不是公开资格或ingestion状态；正文未保存的记录不能伪造。历史已保存artifact只有来源/哈希可核才能补入镜像，派生改写不冒充原文。
- 用完整readonly SQLite导出+同目录receipt与一条current symlink提升；拒绝坏包/WAL/错hash，保留旧快照及可回滚路径。页面从runtime读取全文，源数据不嵌入公开HTML/JS。
- 知识生产先复用匹配source hash/recipe的已有成功产物和receipt；需要新生成时先核既有原生Hermes主生产面/解释器绑定，再执行，不从未配置的Mac变量推断所有主生产面不可用。业务provider与Codex角色独立，不在失败后更换harness/provider。
- 文章及跨源Wiki沿既有标准化/接受/合并/构建合同；稳定source ref和独立URL同时验证，引用逐字可读。超限原文保全并报告待分段；需要分段时只在真实样本证明确需后复用已安装提取/现有分段，避免新ETL。
- 实体/关系读面采用已有SQLite公开投影；旧LightRAG/Qdrant主生产图保留。当前不用为未生产化的深问API/MCP先做跨机器全图快照复制；该旧R6支线继续保留，不是本轮本地使用的前置。
- 一条可重跑本地命令接续文章镜像→知识候选/接受→既有build-release→manifest验证→原子提升。初期在Mac既有8788本地站点自动更新发布，沿已有原生scheduler注册，勿新增队列、数据库或第二同职责生产者；云主机/公网拓扑留原决策。
- 可写Sol主控按票推进，Luna隔离取证/机械工作/定向测试，Sol分别复审Spec与Standards；无孙代理，常规并发2–3、硬上限4。用户已授权规划后执行，既有接口/TDD接缝沿用，无再次设计审批；新不可逆/凭据/付费扩张仍不在范围。

## Testing Decisions

只测行为：真实ingest_from_db入口与schemafixture验证双轨/8列/失败重入边界；真实翻译入口验证部分成功保存且非零；source packet→既有producer→accepted/build与HTTP验证语义引用；临时双源快照经实际current提升、API/已有本地确定性浏览器验证全历史分页/正文/链接/刷新。保持原公开95基线，正常重跑无重复加工，坏包保前版。

每个修改先一个真实入口RED→最小GREEN，使用匹配小测试/编译及生产读回；不跑有副作用全套。模型/浏览器/transport问题与产品失败分账，同一分支两次失败停止并重新取证。当前browser-client本地URL被客户端阻断是该route阻塞；CLI API200独立成立，不能由其宣称新浏览器验收。
