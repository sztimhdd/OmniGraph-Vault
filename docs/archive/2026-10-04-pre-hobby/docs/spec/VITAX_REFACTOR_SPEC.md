# VitaX 重构规格

2026-09-09 修订。状态：用户已授权重新规划并开始实施；全项目未验收。实施入口为[当前计划](../superpowers/plans/2026-09-09-vitax-product-architecture.md)，依据 ADR 0001–0004。用本规格替代旧迁移顺序；旧验证只保留其实际覆盖范围。

2026-10-02三模块核查后的新增本地文章阅读范围与当前执行编排，见[三模块规格](VITAX_THREE_MODULE_EXECUTION_SPEC.md) / [待执行计划](../superpowers/plans/2026-10-02-vitax-three-module-execution.md)。原文/译文默认不公开，但维护者本地读取不以ingestion或公开accepted为前置；本轮仅规划，不恢复此前生产实施。

## Problem Statement

[KNOWN] 用户需要能持续自主产出知识、支持免费浏览搜索及可选深度研究的专业站点。旧项目分散在三个环境，已有抓取、图检索、Wiki和站点代码，但历史健康报告不能证明当前日更闭环。用户明确反对为了兼容旧 pipeline 而耗费重构资源，也不希望为了缩减服务牺牲 KG 能力。

## Solution

[INFERRED] PC 单写知识生产，单云服务已发布内容与 MCP。以来源、文章修订、已接受知识修订和 release 为合同；SQLite承载业务实体/关系/证据与公开读模型，图/向量实现以实测选取。Wiki持续更新，普通搜索无需生成模型，复杂问题选择有界 BYOLLM AgentRAG。先复用成熟代码与单一调度入口，出现具体缺口再增加组件。

## User Stories

1. [KNOWN] 读者可浏览真实文章解读和专题 Wiki，查看出处与关键图片。
2. [KNOWN] 读者可免费搜索中英文概念、缩写和版本，并定位到公开证据。
3. [KNOWN] 读者可查看实体间有类型、有来源的关系，而不是只有装饰性链接。
4. [KNOWN] 访客可自带模型完成跨文章比较、补查与带引用回答。
5. [INFERRED] 无证据或有冲突时，答案明确说明，不能编造证据闭环。
6. [KNOWN] 维护者可复用已有文章、翻译、Wiki、图片和人工修订，不必全量再加工。
7. [KNOWN] PC每天自动生产知识，云端在PC离线时仍能读取完整已发布版本。
8. [KNOWN] 发布失败继续服务前版；08:00只提升验证成功的版本。
9. [KNOWN] 私有原文、后台资料及访客key不能经站点、搜索或MCP泄露。
10. [KNOWN] 额度耗尽暂停相关模型工作，不自动换付费路线或兑换额度。
11. [KNOWN] Hermes普通修复不成功时升级Codex，仍阻塞再通知用户；受保护动作遵循ADR0002。
12. [KNOWN] 单云还承载vitaclaw-site，但不能把它当作VitaX站点的默认替换对象。

## Implementation Decisions

### 2026-09-10：旧内容试导入前置（部分执行）

[KNOWN] 用户要求把已有文章/译文的转换纳入下一轮。复用现有规格与VX-012/VX-009子票，不新建tracker。旧内容试导入不再等待云端切换；现场只读盘点已完成：成功入库文章并集1,257篇，数据库原文1,216份、全文译文1,203份，41篇待旧artifact恢复；正式导出仍须核实所选字段与当次快照。

[KNOWN] VX-012A 已接受；VX-012B 已实际导入20篇私有候选并验证零LLM、幂等与原文/译文保全。13篇结构质量通过、7篇待核，20篇均未获公开资格；全量质量/长度筛选和012C尚未执行。

[INFERRED] 当前先完成安全公开投影与真实两来源读者站，再用导入旧知识验收009B。原文/译文/人工资产继续在私有候选保全，公共内容只来自显式accepted knowledge/Wiki和必要证据；不能把迁移理解为全文自动公开或旧知识自动重新审核。未知历史字段不补造，不为满足新schema重新翻译/调用模型。

[INFERRED] 验证沿既有“内容资产→公开投影→build→fresh读取”及浏览器/HTTP/MCP入口，不加通用ETL平台。导入统计、公共合格统计与语义审核状态分别报告。样本试导入与全量增量迁移共用一个入口；生产切换仍依赖原发布/恢复/查询/日更验收。

### 2026-09-10：质量筛选与全量候选

[INFERRED] 迁移成功、质量结论和公开资格独立记录；原始资产保全，筛选只决定活跃索引/待核状态。按有效正文统计中英文长度，识别壳页、重复、乱码、疑似截断和译文异常，短文仅标记而不机械淘汰。全量规则预览不等于全量迁移，也不认证语义质量。复用旧成果，迁移零LLM；补加工另排队并复用已接受结果。

[INFERRED] 012A→012B后，由012C用同一入口完成全量隔离候选与缺失清单；与009站点共享读取可并行，均不等待云切换。最终生产切换仍需发布、日更、BYOLLM与恢复门。完整顺序以核心项目计划为准。

### 原有决策

- [INFERRED] 四个逻辑对象不用四个服务实现。公开投影DTO是知识包的受限读视图，不是第二个私有内容目录。
- [INFERRED] 稳定来源与多次捕获分开；文章内容变化产生新修订；Wiki与关系支持多个来源证据。历史未知字段保留null，模型输出不是可确定复现的真值。
- [INFERRED] 公开内容采用白名单；知识和关系不得引用缺失或私有证据。完整原文/翻译、原始文件与运行记录默认私有。
- [INFERRED] SQLite图以业务实体、关系与证据为主。最短路径、任意子图、社区发现和通用本体编辑器不进入首版。
- [INFERRED] LightRAG与Qdrant保留隔离对照，未经质量/资源验证不退役，也不默认接入新公网。首条链不同时替换向量库、embedding与图算法。
- [INFERRED] AgentRAG先复用有界循环，内部返回证据，外层综合；工具次数、候选数、上下文、时间和模型预算分别限制。查询侧所有模型步骤由BYOLLM承担；不共享用户历史，不回退站点Key。
- [INFERRED] 接入用户提供的站点，HTTP/MCP共用读逻辑。每个请求固定release，页面、证据、图片和选定索引保持同一版本。
- [INFERRED] 日更先复用单一现有调度入口。Prefect只有替代明确的重复调度工作时才考虑，不是前置依赖。
- [KNOWN] ADR0002四类例外持续有效；没有自动commit/push，生产变更必须有具体范围与验收。

## Testing Decisions

[INFERRED] 主要验证缝隙是“接受知识包→构建公开版本→从新进程读取”。使用真实临时SQLite与CLI验证文章/Wiki检索、关联证据、多来源引用、私有哨兵拒绝、缺失引用拒绝、失败不覆盖既有文件。已有Agent测试在外部检索边界替身下检查取证语义和实际下传限制，不运行模型。

[INFERRED] 真实来源、站点浏览器、BYOLLM、发布与备份分别完成对应产品验收；离线合成测试不证明中文召回、语义质量、生产健康或迁移成功。只运行与变更相关且已确认隔离的测试，旧测试故障不能用新组件绕过。三个决定性验证及先后顺序见计划，不额外搭benchmark平台。

## Out of Scope

[INFERRED] 首个本地切片不包含抓取、LLM生产、图片传输、网页部署、真实BYOLLM、旧数据迁移、生产调度切换和引擎胜负结论；这些属于后续工单。全项目不包含新增通用图引擎、第二Agent运行时、微服务平台或全量旧布局兼容工程。
