# 以产品目标和当前实践重构，不以遗留实现一致为目标

[KNOWN] 2026-09-09 用户明确要求把时间投入架构与 pipeline 理解、行业实践和核心 GitHub 项目调研；允许彻底重构与优化。旧 pipeline 不具有最佳实践地位，项目目标是专业知识产品，而非旧代码搬迁。

[INFERRED] 后续先设计独立的文章、证据、知识产物和发布合同，再决定现有组件的保留、替换、重写。保留原始数据、来源关联、访问权限和有效业务行为；不要求新实现复制旧文件布局、脚本调用链、hash 格式、所有历史行为或多套状态标记。

[KNOWN] 已完成的合成图/Wiki 验证保留为有限参考证据，不能使旧架构成为新架构验收标准。原始资料和无关 WIP 继续保护；ADR 0001 的 PC 生产/单云服务分工及 ADR 0002 四类权限例外不变。

[INFERRED] 采用模块化重建与小规模真实数据验证。优先验证读者获得的内容质量、检索证据、日更自主性和单位有效文章成本；不为废弃路径继续追加兼容层和探针。仅当真实结果或明确风险需要时重复测试和独立复核。

[KNOWN] 本决策接受的是用户明确的方向调整。具体库/版本、数据库后端和性能结论仍须调研与有界实验，不因本 ADR 自动升级生产依赖、迁移数据或部署新架构。
