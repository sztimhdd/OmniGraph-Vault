# VX007 offline publication manifest contract

Status: local source contract only. This is not a deployment record.

`lib.publication_manifest.validate_manifest(manifest_path, root)` checks a
JSON manifest for one `release_version`. Every declared artifact must carry
that same version, remain under `root`, be a regular file rather than a
symlink, and match its SHA-256 digest.

The manifest has two disjoint sections:

- `private_backups`: `sqlite`, `vector`, and `graph_kv`. These are private
  release inputs and must not be treated as public read artifacts.
- `public_read_collection`: `wiki`, `images`, and `public_content`. These are
  the public artifacts associated with the same release version.

`public_content` is an opaque public release artifact. It may package public
body content and search indexes projected from that public content, including
an FTS or vector index. This slice neither parses that package nor claims that
such indexes exist, are complete, or are usable.

When a runtime read path is later implemented, it must bind its content, Wiki,
image, and any packaged search-index reads to the validated
`public_read_collection` artifact paths for the selected `release_version`. It
must never resolve anonymous or public requests through `private_backups.sqlite`,
`private_backups.vector`, or their containing directories. This validator does
not enforce that runtime binding; export and query acceptance must separately
verify that the package forms an independent public read collection.

Both sections require exactly their listed components. Missing components,
unknown components, version drift, duplicate artifact paths, path traversal,
symlinks, missing files, invalid JSON, and hash mismatches are rejected. For
each artifact path, every component below the declared manifest root must be a
non-symlink; the validator does not inspect canonical path components above
that root.

The validator is standard-library-only and offline. It does not open SQLite,
contact a vector or graph/KV backend, build snapshots, update an active
pointer, publish files, load environment credentials, or make model calls.

This contract verifies only a file-level release projection. It does not prove
runtime query isolation, service authorization, or an atomic cross-store
snapshot. Those properties require separate runtime and deployment evidence;
the plan assigns the private-sentinel negative query to VX009.
