# VitaX 读者体验核查（内容 / UX / 附加功能与搜索）

2026-10-03。只操作浏览器可见界面；没有用源码、数据库、API回包或上一轮测试替代本轮用户体验。用户指定Browser，当前工具目录未提供其独立入口，通过可用cua_repl的应用内浏览器及其公开Browser UI接口完成。窗口默认尺寸，未另验移动端、屏幕阅读器或全部历史文章。站点release `release-local-ui-bc3213253a9f`。

额度起点29%，收尾30%，本轮上限32%（共享账户，按整百分点观测）。本轮仅访问、记录issues和规划；未改产品代码、生产服务或数据，未commit/push，未启动子代理。

实际路径：首页 → 中文上下文检索 → 文章筛选 → 解读 → 站内返回；首页 → Harness Wiki与证据；两个同名RAG → 不同关系；文章库 → TLA检索/RSS筛选 → 原文/译文切换；两条同标题Raccoon Heist → 原文章来源；ELF文章 → 可见正文命中位置；公开TLA零结果 → 文章库。

## 已验证可用

- 首页14条公开知识；文章库显示10130来源记录、2960原文、1753译文，默认仅有正文。
- 中文“上下文”9条，文章筛选7条，筛选保留检索词。
- 原文章能打开，已有译文按钮可切到中文；缺译文按钮禁用。
- 原文库有来源筛选、翻页与正文过滤；浏览器Back可回到带q的列表。
- 来源引文和实体关系可展开。不得把本轮问题写成站点整体不可用。

## 发现与接受边界

### #100 · P1 · 内容 · 原文/译文混合格式没有形成可读展示

- 路径：`/library/rss/189924、/library/rss/2103、/library/rss/121705`
- 实际观察：RSS正文露出 #、##、反引号、`<a href>`、`<br />`；Raccoon Heist图片仅显示 `![说明](地址)`，代码块仍是原始围栏文本。
- 读者影响：阅读和理解代码/图示受阻。仅“数据存在”不能作为“可读性通过”。
- 最小方向：先沿展示调用链确认格式来源，再复用既有展示能力；仅派生阅读视图，不改原文，不为格式化重新调用LLM。
- 退出门：原文与译文的标题、段落、列表、代码、链接和已可用图片正常展示；TLA+符号保留，原文hash不变，HTML脚本和危险URL不执行。

### #101 · P1 · 内容 · 链接边界吞入标点、相邻链接或中文句子

- 路径：`/library/rss/189924（原文与已有译文）`
- 实际观察：原文href包含 /tla-from-first-principles/). 和 /2026-09-26-reachability/)with；译文Springer链接吞入“、[2](https://learntla.com/)）和[推广]…”及中文句子。
- 读者影响：本地读者点击会访问错误目标，复制链接也不可靠。
- 最小方向：在展示边界定位原始数据/解析器各自的问题，复用链接处理；保留合法括号URL，不把一概截断当修复。
- 退出门：相邻Markdown链接独立；中文/英文标点不进入href；Wikipedia括号URL仍完整；两种语言样本都实际点击或核对目标。

### #102 · P2 · 内容 · 相同来源文章以重复记录挤占阅读列表

- 路径：`TLA检索，RSS结果中的 /library/rss/130043 与 /library/rss/121705`
- 实际观察：相同Raccoon Heist标题，原文章来源分别为 https://simonwillison.net/2026/Aug/5/raccoon-heist/ 和同地址#atom-everything；列表没有版本/来源区别提示。
- 读者影响：重复阅读且结果数量被重复记录放大。未声称两条正文完全相同。
- 最小方向：先按去fragment后的来源地址在列表归组，保留所有记录和不同修订；不删除原库，也不按标题模糊合并。
- 退出门：重复来源以一组展示，可展开两条原始记录/版本；不同URL同标题不误合并。

### #103 · P2 · 内容 · Wiki缺稳定读者结构与清晰的引用呈现

- 路径：`/wiki/legacy-harness`
- 实际观察：Harness定义后正文主要围绕EvoTrainer和smevals案例，段中出现rev-…；章节是一/二/三的长段，引用中又出现“线束工程”，与正文“智能体工作框架”措辞不同。
- 读者影响：通用词条与近期案例边界不清，无法直接从段落定位对应来源。术语差异是编辑意见，未据浏览器判断原作者或事实错误。
- 最小方向：采用简短定义/组成/适用边界/案例的固定读者结构，已知来源标识映射为可点击编号；原始引文保留，可加术语说明。
- 退出门：定义与案例区分；正文不露内部revision hash；来源编号可定位证据，历史引文不被无证据改写。

### #104 · P2 · 内容 · 列表缺判断是否值得阅读的基本信息

- 路径：`/、/library`
- 实际观察：知识首页只见类型、ID和标题，按“release中稳定标识排序”；文章库只标RSS/公众号与正文/译文，行内没有具体来源、日期或摘要。
- 读者影响：难判断新旧、作者与主题，同标题内容难比较；已有译文的英文标题也不能帮助快速中文选读。
- 最小方向：使用现有来源域名、标题/译文标题和已知时间，补一行摘要/命中片段；未知时间明确标未记录，不用LLM补日期。
- 退出门：卡片有具体来源和标明含义的时间，原文/译文语言清楚；支持日期顺序，不能把收录或release时间伪作文章发布日期。

### #105 · P1 · UX · 原文、解读、Wiki与证据阅读链不连通

- 路径：`/article/article-rss-173855、/wiki/legacy-harness、/library/rss/189924`
- 实际观察：解读和Wiki的证据链接只指向外站，未看到直接打开本地原文/译文；原文页没有其解读、相关Wiki入口。
- 读者影响：用户要在两个列表中重新搜索，已保存内容也被迫依赖外站访问。
- 最小方向：仅在本地私有阅读启用时，用真实来源映射连接既有页面；不猜slug，不扩大公网全文边界。
- 退出门：从一篇解读能读本地原文/译文再返回；存在相关Wiki时可达；public-only部署不暴露私有内容。

### #106 · P1 · UX · 返回列表丢失检索、筛选与阅读位置

- 路径：`/?q=上下文&kind=article → 解读 → 返回知识列表；/library?q=TLA&source=rss → 原文 → 返回文章库`
- 实际观察：前者7条结果返回后变14条、检索框清空；后者返回后q清空、来源回到全部、页码1。浏览器Back可恢复，因此是站内返回行为问题。
- 读者影响：连续选读需要反复输入和翻页。
- 最小方向：复用URL查询参数保存returnTo并验证为站内地址，恢复列表位置；不引入全局状态框架。
- 退出门：文章/知识两条路径返回保留q、kind/source、has_body和offset；刷新、直达URL有合理回退，返回参数不能指向站外。

### #107 · P2 · UX · 内部标识和工程术语占据主要阅读空间

- 路径：`首页、Wiki正文、证据区、实体关系区`
- 实际观察：release、article-rss-…、rev-…、evidence-…、paragraph:1和enhances/improves_retrieval_stage_of直接显示。
- 读者影响：普通读者分不清内容信息与实现细节，列表密度降低。
- 最小方向：读者视图只显示来源、日期和中文关系说明；原始ID/type保留在原生details技术信息中。
- 退出门：普通阅读不需要理解内部ID；维护者仍可展开查看和复制，未知关系类型有明确原始值回退。

### #108 · P2 · UX · 同名实体和关系展示无法清楚区分与定位

- 路径：`首页实体与关系栏`
- 实际观察：两个“检索增强生成（RAG）”按钮分别展开GraphRAG→RAG和上下文检索→RAG；选中按钮旁未直接出现对应结果，关系容器在清单尾部。
- 读者影响：看起来像重复或空点击，不知道两节点区别与关系属于哪里。
- 最小方向：先做展示层同名分组/来源区分和就地展开；保留原ID与证据，不自动合并底层图节点。
- 退出门：两组RAG关系均可找到，展开结果邻近选中项且带来源；不丢边/证据，不误并异义实体。

### #109 · P1 · 搜索 · 同一词在两个内容范围无法接续检索

- 路径：`文章库TLA有结果；公开知识首页TLA零结果`
- 实际观察：公开零结果只有清空词，顶部文章库链接不携带TLA；进入文章库必须重输。两种范围不同本身不是bug。
- 读者影响：容易把“尚无解读”误解为“未保存文章”。
- 最小方向：本地模式提供保留q的范围切换/继续在原文库检索；保留原文、解读、Wiki标签与隐私边界。
- 退出门：TLA公开零结果能一击查看原文结果；上下文仍可筛文章/Wiki；public-only没有私有检索入口。

### #110 · P2 · 搜索 · 英文词搜索把URL子串当主题命中

- 路径：`文章库搜索TLA、来源RSS → Dealing with weird ELF libraries`
- 实际观察：可见原文中第一个tla位于 `<a href="https://gitlab.com/...">`，标题也不含TLA。
- 读者影响：技术术语检索出现明显噪声，不能仅凭命中数量认为好用。
- 最小方向：先核现有查询/FTS能力；英文词边界、展示文本检索及标题优先走现有路径；中文短词/技术符号保持支持。
- 退出门：TLA/TLA+能找到目标而不因gitlab.com误入；上下文、C++等不退化；实际匹配正文仍可检索，无新搜索服务或每次LLM调用。

### #111 · P2 · 搜索 · 结果没有命中说明与本次结果规模

- 路径：`文章库TLA检索`
- 实际观察：仍显示全站10130/2960/1753，结果只有标题、状态和页码；正文命中无片段/高亮，没有本次匹配数说明。
- 读者影响：看不出结果为何相关、是否已搜完，容易混淆全站统计与搜索统计。
- 最小方向：补标题/正文/译文命中片段和明确的本页/匹配数标签；先复用limit+1，不为精确total强建新索引。
- 退出门：ELF等正文命中有可解释片段；全站统计与结果统计分开；有下一页时明确还有更多，不能伪称本页数为全部数。

### #112 · P2 · 附加功能 · 缺具体来源、日期与译文可用性筛选

- 路径：`/library`
- 实际观察：来源只有全部/公众号/RSS，另有仅有正文；没有具体公众号/RSS站点、时间或只看译文的控制。
- 读者影响：大量文章难缩小选读范围。属于新增能力建议，不是现有控件失效。
- 最小方向：优先复用已有字段与原生控件，先做译文布尔筛选和明确日期；具体账号字段存在再接入，不建标签平台。
- 退出门：两个具体来源/日期边界/仅有译文可组合，返回后保留；未知日期不被伪分类。

### #113 · P3 · 附加功能 · 长文章缺轻量续读与章节定位

- 路径：`/library/rss/121705、/wiki/legacy-harness`
- 实际观察：长文章与代码较多，未见目录、阅读位置或继续阅读入口。
- 读者影响：重复进入需滚动找位置。属于体验建议，未宣称全站没有其他收藏方式。
- 最小方向：排在排版/返回修复之后；原生标题锚点和localStorage即可。收藏先用浏览器书签，不新增账号/云同步。
- 退出门：同一文章和语言可续读，内容修订时可安全失效；清空本地记录可行，公私数据边界不变。

### #114 · P3 · 附加功能 · 证据缺便捷的引用复制动作

- 路径：`解读/Wiki证据区`
- 实际观察：可阅读引文与外站来源，但没有复制题名+来源链接+引文的动作。
- 读者影响：做笔记要手工拼装且易带入内部hash。属于可选研究辅助。
- 最小方向：一个原生剪贴板按钮复制纯文本来源引用，不默认导出全文，不引入PDF/笔记平台。
- 退出门：复制内容是可读题名、原始来源URL、引文与已知日期；未知日期不编造，有复制成功/失败反馈。
